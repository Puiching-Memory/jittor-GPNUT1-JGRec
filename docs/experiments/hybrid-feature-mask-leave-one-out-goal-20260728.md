# Hybrid 特征掩码留一法：本地实施目标

## 1. Goal

在不依赖服务器、GPU 训练或线上反馈的前提下，为 Hybrid 基础融合补齐“留一法”
（leave-one-group-out）候选：以所有已启用特征组的完整集合为基准，每次只移除一个
特征组，使后续 rolling-origin 与 external gate 能识别“某组特征是否在拖后腿”。

本轮目标是完成可验证的本地工程闭环，不宣称模型效果提升，也不生成提交包。

## 2. Verifiable Target

本地实现必须同时满足：

1. 每个已启用、非空且移除后仍有特征可训练的特征组，都有一个候选精确等于
   “完整掩码减去该组”。
2. 完整掩码本身存在，作为留一法的共同基线。
3. 默认候选列表中不存在索引完全相同的重复掩码，避免重复训练。
4. 原有递进加法候选及其名称保持不变，避免破坏既有 checkpoint/实验引用。
5. 即使某个留一候选与原候选索引相同，仍可用稳定别名
   `loo_without_<group>` 精确冻结并复现，但默认扫描只训练一次。
6. 被配置禁用或在当前特征宽度下为空的组，不产生无意义的留一候选。
7. 本地预检报告能枚举完整掩码、各组留一映射、去重状态和协议边界。
8. 测试覆盖正常配置、禁用特征组、重复候选别名和未知冻结候选错误。

## 3. Boundaries

### In Scope

- Hybrid 融合特征组目录与留一候选生成。
- 原递进加法路径兼容。
- 唯一候选去重及稳定冻结别名。
- 纯本地、无需训练数据的结构预检。
- 单元测试、回归测试、静态检查和实验说明。
- 与现有标准验证协议的衔接说明。

### Out of Scope

- GPU 训练、rolling-origin 多折实际跑分。
- 长跨度 external holdout 的首次打开。
- 依据单折 MRR 或线上分数选取留一候选。
- 生成或提交预测包。
- 修改特征定义、模型结构或融合损失。

## 4. Current State

当前 `_feature_masks()` 只构造两条递进加法路径。它能回答“逐步加入某组后是否变好”，
但不能系统回答“在完整候选上移除某组是否变好”。此外，一些“完整集减一组”的结果
可能已经与原递进候选重合；若直接追加所有留一候选，会造成相同索引重复训练。

## 5. Phased Route

### Phase 1 — Contract

- 固化已启用特征组、完整掩码和留一掩码的定义。
- 固化默认扫描去重、冻结别名可寻址、原名称不变三项兼容规则。

### Phase 2 — RED

- 先写测试证明当前实现缺少系统留一覆盖。
- 测试失败必须由“缺少完整掩码/留一候选/别名解析”导致，而不是环境或夹具错误。

### Phase 3 — GREEN

- 以最小实现生成候选目录和留一映射。
- 将目录接入 `_feature_masks()`，不改融合训练其余行为。

### Phase 4 — Refactor and Evidence

- 将结构审计输出为本地预检 JSON。
- 运行相关回归测试和 Ruff。
- 记录 RED、GREEN、回归与本地协议证据。

## 6. Per-Phase Rules

- 不读取 external holdout 标签或指标。
- 不把单一指标作为候选结论。
- 不因留一别名而重复训练相同索引。
- 不重命名原候选。
- 不生成提交包。
- 后续实际比较必须先冻结精确候选，再经过 rolling-origin 多折稳定性门禁，最后只打开一次
  external holdout。

## 7. Todos and Proof

| Todo | Required proof |
|---|---|
| 建立完整掩码 | 测试断言完整掩码等于所有已启用非空组的并集 |
| 补齐逐组留一 | 测试逐组断言 `full - group` 存在 |
| 防止重复训练 | 测试断言默认候选索引元组全局唯一 |
| 保留旧候选 | 测试断言既有候选名称仍存在 |
| 支持冻结别名 | 测试断言 `loo_without_<group>` 精确解析并保留请求名称 |
| 处理禁用/空组 | 测试断言这些组不进入留一目录 |
| 生成本地证据 | 预检 JSON 明示未读 external、未跑指标、未生成提交包 |
| 防止回归 | 相关 Hybrid/CLI/checkpoint 测试与 Ruff 通过 |

## 8. Dry Run

以默认 Hybrid 特征为例：

1. 收集 `stats/prior/target/structure/profile/tower/gnn/seq` 中实际启用且非空的组。
2. 取这些组的索引并集作为 `full`。
3. 对每个组计算 `full - group`，登记别名 `loo_without_<group>`。
4. 先保留原递进候选，再加入尚未出现过的完整/留一索引。
5. 若留一索引与原候选重合，目录把别名映射到该索引，但默认扫描不新增重复项。
6. 当配置冻结到该别名时，只返回该别名及其精确索引，保证正式验证可复现。
7. 本地预检只审计结构；真正胜负留给 rolling-origin 与 external gate。

## 9. Go / No-Go

**Go（本地实施）**：目标是纯结构性补全，可由单元测试完整验证，不需要服务器。

**No-Go（效果结论/提交包）**：在 rolling-origin 多折与 external gate 尚未执行前，不得声称
某个特征组有害，也不得据此生成提交包。

## 10. Plan Rewrite Notes

原计划只提出“12 组掩码补留一法”。本目标将其改写为一个可复现的候选目录：

- 从“追加若干掩码”改为“完整基线 + 每个已启用组的精确补集”。
- 从“名称即候选”改为“唯一训练候选 + 稳定实验别名”，解决重复计算与复现冲突。
- 从“本地挑最好”改为“本地只完成结构门禁，效果选择交给标准验证协议”。

## 11. Drift Diagnosis

此任务本身不是训练—服务分布漂移修复。需要防止的计划漂移是：

- 把单折最优误当成留一结论；
- 因候选重名/重索引重复训练；
- 在 external 或线上结果之后反向扫描特征组；
- 用新增留一候选替换或重命名既有候选。

上述行为均不属于本轮本地完成范围。
